## What are prefix sums and difference arrays?

Prefix sums and difference arrays both maintain an auxiliary array to describe the state of the current array. They are similar, but their purposes and implementation methods are different.

**Prefix sums**: A prefix sum array stores the running total up to each position, so any range sum becomes a single subtraction. Generating it takes \\(O(n)\\) preprocessing, and each query then takes \\(O(1)\\). In 2D, we will need the inclusion-exclusion principle as well.

**Difference arrays**: A difference array can achieve uniform range updates in \\(O(1)\\) time complexity per operation. After the difference array is generated, the original array can be restored by performing a prefix sum operation on it.

## Prefix Sums

The recurrence for prefix sums looks something like this:

<LangTabs items={['C++', 'Python']}>

<Tab value="C++">

```cpp
s[i]=s[i-1]+v[i];
```

</Tab>

<Tab value="Python">

```python
s[i] = s[i - 1] + v[i]
```

</Tab>

</LangTabs>

Here array `s` is the prefix sum array, and `v` is the original array.

So for an array of length `n`, we can generate the prefix sum array `s` with the following code (arrays are 1-indexed, and `n` is at most 1000):

<LangTabs items={['C++', 'Python']}>

<Tab value="C++">

```cpp
int v[1001];
int s[1001];
memset(v,0,sizeof(v)); // initialize
memset(s,0,sizeof(s));
int n;
cin>>n;
for(int i=1;i<=n;i++){
    cin>>v[i]; // input
}
for(int i=1;i<=n;i++){
    s[i]=s[i-1]+v[i]; // generate
}
```

</Tab>

<Tab value="Python">

```python
n = int(input())
v = [0] + list(map(int, input().split()))   # v[0] = 0, so v is 1-indexed
s = [0] * (n + 1)                            # initialize
for i in range(1, n + 1):
    s[i] = s[i - 1] + v[i]                   # generate
```

</Tab>

</LangTabs>

Just like that, we get the prefix sum array `s`.

As mentioned earlier, the prefix sum array can quickly find a range sum using the following method:

<LangTabs items={['C++', 'Python']}>

<Tab value="C++">

```cpp
int sum=s[j]-s[i-1];
```

</Tab>

<Tab value="Python">

```python
total = s[j] - s[i - 1]
```

</Tab>

</LangTabs>

Here, `sum` is the range sum from `v[i]` to `v[j]`. `s[j]` covers everything up to `j`, and `s[i-1]` is the part before `i`, so subtracting leaves exactly the range. Each query takes \\(O(1)\\).

## Difference Arrays

Difference arrays are similar to prefix sums; both process arrays.

As usual, let's jump straight to the recurrence:

<LangTabs items={['C++', 'Python']}>

<Tab value="C++">

```cpp
d[i]=v[i]-v[i-1];
```

</Tab>

<Tab value="Python">

```python
d[i] = v[i] - v[i - 1]
```

</Tab>

</LangTabs>

`d` is the difference array, and `v` is the original array.

Similarly:

<LangTabs items={['C++', 'Python']}>

<Tab value="C++">

```cpp
int v[1001];
int d[1002]; // size n+2, because an update below touches d[j+1]
memset(v,0,sizeof(v)); // initialize
memset(d,0,sizeof(d));
int n;
cin>>n;
for(int i=1;i<=n;i++){
    cin>>v[i]; // input
}
for(int i=1;i<=n;i++){
    d[i]=v[i]-v[i-1]; // generate
}
```

</Tab>

<Tab value="Python">

```python
n = int(input())
v = [0] + list(map(int, input().split()))   # v[0] = 0, so v is 1-indexed
d = [0] * (n + 2)                            # size n+2, because an update below touches d[j+1]
for i in range(1, n + 1):
    d[i] = v[i] - v[i - 1]                   # generate
```

</Tab>

</LangTabs>

Now we have the difference array. And just like I described earlier, the whole point of creating a difference array is to uniformly update all numbers within a range.

Once we have the difference array, how do we restore the original array? We use the exact same method as the prefix sum array generation:

<LangTabs items={['C++', 'Python']}>

<Tab value="C++">

```cpp
for(int i=1;i<=n;i++){
    v[i]=v[i-1]+d[i];
}
```

</Tab>

<Tab value="Python">

```python
for i in range(1, n + 1):
    v[i] = v[i - 1] + d[i]
```

</Tab>

</LangTabs>

Here is how it works:

```
Index:                                  0, 1, 2, 3, 4, 5
Original array:                         0, 1, 2, 3, 4, 5
Difference array:                       0, 1, 1, 1, 1, 1
Prefix sum op on the difference array:  0, 1, 2, 3, 4, 5
```

How do we implement updates?

Now our goal is to add 1 to each element from the `i`-th to the `j`-th position in array `v`. Using a regular loop, the complexity is \\(O(j-i)\\).

<LangTabs items={['C++', 'Python']}>

<Tab value="C++">

```cpp
for(int t=i;t<=j;t++){
    v[t]++;
}
```

</Tab>

<Tab value="Python">

```python
for t in range(i, j + 1):
    v[t] += 1
```

</Tab>

</LangTabs>

But when the gap between `i` and `j` is large, you'll get a TLE.

However, if we modify the difference array directly, the story is completely different. For example, adding 1 to each element from position 1 to position 3:

```
Index: 0, 1, 2, 3, 4, 5
Orig:  0, 1, 2, 3, 4, 5
Diff:  0, 1, 1, 1, 1, 1
Mod:   0, 2, 1, 1, 0, 1
Sum:   0, 2, 3, 4, 4, 5
```

As you can see, we only modified two values, yet we updated the entire range. The method is now crystal clear:

<LangTabs items={['C++', 'Python']}>

<Tab value="C++">

```cpp
d[i]+=c;
d[j+1]-=c;
```

</Tab>

<Tab value="Python">

```python
d[i] += c
d[j + 1] -= c
```

</Tab>

</LangTabs>

This adds `c` to every value between `i` and `j`.

Note that difference arrays work best when all the updates come first and the array is read afterwards. We do all the updates, restore the array once, and then answer the queries.

## 2D Prefix Sums

Sometimes, a 1D prefix sum just doesn't cut it, so we can introduce 2D prefix sums.

The principle is similar. Here is the generation code. A 1001 by 1001 `int` array takes about 4 MB, so declare these arrays globally. Local arrays of this size can overflow the stack, and global arrays start out filled with 0 anyway.

<LangTabs items={['C++', 'Python']}>

<Tab value="C++">

```cpp
int v[1001][1001];
int s[1001][1001]; // 2D prefix sum array

int main(){
    int n;
    cin>>n;
    for(int i=1;i<=n;i++){
        for(int j=1;j<=n;j++){
            cin>>v[i][j];
        }
    }
    for(int i=1;i<=n;i++){
        for(int j=1;j<=n;j++){
            s[i][j]=s[i-1][j]+s[i][j-1]-s[i-1][j-1]+v[i][j];
        }
    }
}
```

</Tab>

<Tab value="Python">

```python
n = int(input())
v = [[0] * (n + 1) for _ in range(n + 1)]
s = [[0] * (n + 1) for _ in range(n + 1)]   # 2D prefix sum array
for i in range(1, n + 1):
    row = list(map(int, input().split()))
    for j in range(1, n + 1):
        v[i][j] = row[j - 1]
for i in range(1, n + 1):
    for j in range(1, n + 1):
        s[i][j] = s[i - 1][j] + s[i][j - 1] - s[i - 1][j - 1] + v[i][j]
```

</Tab>

</LangTabs>

For the sum query, we also need the help of the inclusion-exclusion principle. To sum the rectangle with top-left corner `(x1,y1)` and bottom-right corner `(x2,y2)`, subtract the part above it and the part to its left, then add back the corner that was subtracted twice:

<LangTabs items={['C++', 'Python']}>

<Tab value="C++">

```cpp
int sum=s[x2][y2]-s[x1-1][y2]-s[x2][y1-1]+s[x1-1][y1-1];
```

</Tab>

<Tab value="Python">

```python
total = s[x2][y2] - s[x1 - 1][y2] - s[x2][y1 - 1] + s[x1 - 1][y1 - 1]
```

</Tab>

</LangTabs>

## Example Problem 1: J5/S2 Beams of Light

Theory is easier to understand with practice. Let's look at the problem first:

<ProblemSections component={BeamsOfLight} meta={beamsMeta} />

In other words:

Each light at position `sp` with width `w` illuminates the parking spaces from `sp-w` to `sp+w` (cut off at space 1 and at space `nos`), and we need to answer `nt` queries on whether a specific parking space is illuminated.

If we use a loop to mark every space of every beam, one beam can touch up to 500000 spaces, and we might have to mark 500000 times.

In the worst-case scenario, we would need to execute \\(2.5 \\times 10^{11}\\) loop iterations, which is a guaranteed TLE.

But if we use a difference array, the complexity of each mark is \\(O(1)\\).

In the worst case, the total operations are roughly \\(500000 \\times 2\\) (marking) + 500000 (generating the corresponding original array) + 500000 (queries).

This way, it won't time out.

Two details to watch:

- Clamp the start and end of each beam to the range 1 to `nos`. Then `sub[e+1]` is at most `sub[nos+1]`, which is why `sub` has one extra slot.
- With 500000 queries, input and output speed matters. In C++, turn off I/O syncing and print `'\n'` instead of `endl`, since `endl` flushes the output on every line. In Python, read all the input at once and print once at the end.

Here's the code:

<LangTabs items={['C++', 'Python']}>

<Tab value="C++">

```cpp
#include<bits/stdc++.h>
using namespace std;
int mp[500001];
int sub[500002];
int main(){
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int nos,nol,nt;
    cin>>nos>>nol>>nt; // number of parking spaces, number of lights, number of queries
    for(int i=1;i<=nol;i++){
        int sp,w;
        cin>>sp>>w;
        int s=max(1,sp-w); // start, clamped to 1
        int e=min(nos,sp+w); // end, clamped to nos
        sub[s]++; // mark the start
        sub[e+1]--; // mark the end
    }
    for(int i=1;i<=nos;i++){
        mp[i]=mp[i-1]+sub[i]; // generate the corresponding array
    }
    for(int i=1;i<=nt;i++){
        int p; // query
        cin>>p;
        if(mp[p]==0){
            cout<<"N\n";
        }else{
            cout<<"Y\n";
        }
    }
}
```

</Tab>

<Tab value="Python">

```python
import sys

data = sys.stdin.buffer.read().split()
nos, nol, nt = int(data[0]), int(data[1]), int(data[2])  # spaces, lights, queries
sub = [0] * (nos + 2)
pos = 3
for _ in range(nol):
    sp, w = int(data[pos]), int(data[pos + 1])
    pos += 2
    s = max(1, sp - w)    # start, clamped to 1
    e = min(nos, sp + w)  # end, clamped to nos
    sub[s] += 1           # mark the start
    sub[e + 1] -= 1       # mark the end

mp = [0] * (nos + 1)
for i in range(1, nos + 1):
    mp[i] = mp[i - 1] + sub[i]  # generate the corresponding array

out = []
for _ in range(nt):
    p = int(data[pos])  # query
    pos += 1
    out.append("Y" if mp[p] != 0 else "N")
print("\n".join(out))
```

</Tab>

</LangTabs>

## Example Problem 2: J5/S2 Modern Art

A similar problem, though not a textbook template problem like Beams of Light, it's actually simpler.

Again, let's look at the problem first.

<ProblemSections component={ModernArt} meta={artMeta} />

In other words, the canvas has `x` rows and `y` columns. At the very beginning, all cells are black (`B`), and we need to count the number of gold cells (`G`) after the instructions. Each instruction flips every cell in one row (`R idx`) or one column (`C idx`).

Every cell is initially marked with 0 paint operations.

From this, we get a traditional brute-force simulation idea.

First, I define a grid and initialize every cell to black (for now, a small grid of at most 1000 by 1000):

<LangTabs items={['C++', 'Python']}>

<Tab value="C++">

```cpp
char mp[1001][1001];
for(int i=1;i<=1000;i++){
    for(int j=1;j<=1000;j++){
        mp[i][j]='B';
    }
}
```

</Tab>

<Tab value="Python">

```python
mp = [['B'] * 1001 for _ in range(1001)]
```

</Tab>

</LangTabs>

Then read in the instructions.

For example: `R 1`.

I just run a loop over that row:

<LangTabs items={['C++', 'Python']}>

<Tab value="C++">

```cpp
for(int j=1;j<=y;j++){
    if(mp[idx][j]=='B'){
        mp[idx][j]='G';
    }else{
        mp[idx][j]='B';
    }
}
```

</Tab>

<Tab value="Python">

```python
for j in range(1, y + 1):
    if mp[idx][j] == 'B':
        mp[idx][j] = 'G'
    else:
        mp[idx][j] = 'B'
```

</Tab>

</LangTabs>

A `C idx` instruction works the same way, looping `i` from 1 to `x` over `mp[i][idx]`.

Just like that, I've marked one instruction.

In the subsequent query phase, we traverse the entire grid to find all cells with the value `G`:

<LangTabs items={['C++', 'Python']}>

<Tab value="C++">

```cpp
int ans=0;
for(int i=1;i<=x;i++){
    for(int j=1;j<=y;j++){
        if(mp[i][j]=='G'){
            ans++;
        }
    }
}
cout<<ans;
```

</Tab>

<Tab value="Python">

```python
ans = 0
for i in range(1, x + 1):
    for j in range(1, y + 1):
        if mp[i][j] == 'G':
            ans += 1
print(ans)
```

</Tab>

</LangTabs>

And that solves the problem... right?

Nope.

According to the problem constraints, in the worst-case scenario, our grid (`mp`) might need to be defined as

```cpp
char mp[5000001][5000001];
```

That is far too much memory, so it will definitely MLE (and it won't even compile as a global array).

Maybe some of you might think of optimizing it with dynamic arrays (vectors), but don't forget the time complexity of marking the instructions:

Up to 1000000 instructions, multiplied by a maximum grid width of 5000000: in the worst case, the marking complexity is \\(5 \\times 10^{12}\\), a massive TLE.

So why not borrow the idea behind difference arrays: instead of updating cells one by one, record how many times each row and column is operated on, and work out the cells afterwards.

Initially, the operation count is 0, and the cell is black.

```
Count: 0 1 2 3 4 5
Color: B G B G B G
```

Spot the pattern?

That's right, if the total number of operations on a cell is odd, the cell will be gold.

So how do I calculate the number of operations on a single cell?

Take a 2-row by 2-column grid for example.

```
B B
B B
```

Now execute operation R1:

```
G G
B B
```

All of row 1 has been operated on once.

Now C1:

```
B G
G B
```

Cell (1,1) has been operated on twice in total, so my (1,1) is `B`.

In other words:

Total operations on a cell = Total operations on its row + Total operations on its column.

Now the approach is clear.

1. Count the number of operations for each row and each column.

<LangTabs items={['C++', 'Python']}>

<Tab value="C++">

```cpp
int r[5000001];
int c[5000001];
// ... inside main:
for(int i=1;i<=noa;i++){
    char tp;
    int idx;
    cin>>tp>>idx;
    if(tp=='R'){
        r[idx]++;
    }else{
        c[idx]++;
    }
}
```

</Tab>

<Tab value="Python">

```python
r = [0] * (x + 1)
c = [0] * (y + 1)
for k in range(noa):
    tp = data[3 + 2 * k]
    idx = int(data[4 + 2 * k])
    if tp == "R":
        r[idx] += 1
    else:
        c[idx] += 1
```

</Tab>

</LangTabs>

2. Traverse the entire grid.

    If the total operations on the cell is odd, `ans++`.

    Otherwise, continue.

<LangTabs items={['C++', 'Python']}>

<Tab value="C++">

```cpp
long long ans=0;
for(int i=1;i<=x;i++){
    for(int j=1;j<=y;j++){
        if((r[i]+c[j])%2==1){
            ans++;
        }
    }
}
```

</Tab>

<Tab value="Python">

```python
ans = 0
for i in range(1, x + 1):
    for j in range(1, y + 1):
        if (r[i] + c[j]) % 2 == 1:
            ans += 1
```

</Tab>

</LangTabs>

3. Output the answer.

This traversal costs \\(O(x \\times y)\\), which is fine for small canvases. If your version of the problem allows `x` and `y` up to 5000000, that is far too slow (and the answer can exceed the range of `int`, so use `long long`).

But only the parity of each row and column matters. Let `ro` be the number of rows with an odd count, and `co` the number of columns with an odd count. A cell is gold when its row is odd and its column is even, or the other way around:

\\(\\text{gold} = ro \\times (y - co) + (x - ro) \\times co\\)

Now no grid traversal is needed at all. So, here is the final solution code, which runs in \\(O(x + y + K)\\) time, where \\(K\\) is the number of instructions:

<LangTabs items={['C++', 'Python']}>

<Tab value="C++">

```cpp
#include<bits/stdc++.h>
using namespace std;
int r[5000001];
int c[5000001];
int main(){
    int x,y;
    cin>>x>>y;
    int noa;
    cin>>noa;
    for(int i=1;i<=noa;i++){
        char tp;
        int idx;
        cin>>tp>>idx;
        if(tp=='R'){
            r[idx]++;
        }else{
            c[idx]++;
        }
    }
    long long ro=0,co=0;
    for(int i=1;i<=x;i++){
        if(r[i]%2==1){
            ro++;
        }
    }
    for(int j=1;j<=y;j++){
        if(c[j]%2==1){
            co++;
        }
    }
    cout<<ro*(y-co)+(x-ro)*co;
}
```

</Tab>

<Tab value="Python">

```python
import sys

data = sys.stdin.read().split()
x, y, noa = int(data[0]), int(data[1]), int(data[2])
r = [0] * (x + 1)
c = [0] * (y + 1)
for k in range(noa):
    tp = data[3 + 2 * k]
    idx = int(data[4 + 2 * k])
    if tp == "R":
        r[idx] += 1
    else:
        c[idx] += 1

ro = sum(1 for i in range(1, x + 1) if r[i] % 2 == 1)
co = sum(1 for j in range(1, y + 1) if c[j] % 2 == 1)
print(ro * (y - co) + (x - ro) * co)
```

</Tab>

</LangTabs>
