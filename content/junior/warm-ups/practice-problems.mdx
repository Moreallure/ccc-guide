# Practice Problems

Walkthroughs help, but the skill only comes from solving problems yourself.
The best place to start is real J1 and J2 problems from past contests.

This module works through three of them, from 2025 and 2024. Try each problem
on your own before reading its walkthrough. All three come down to the same
approach as the last module: read carefully, work out what is being asked, and
translate it directly into code.

## J1 Walkthrough: Roller Coaster Ride

</ProblemSections>

### Solution

We need to decide whether you get on the ride. The train holds \\(C \\times P\\)
people and your place in line is \\(N\\), so you ride when:

\\[
N \\leq C \\times P
\\]

Sample 2 checks the boundary: the train holds \\(4 \\times 3 = 12\\) people and
you are 12th in line, so being exactly at the limit still counts.

### Implementation

<LangTabs items={['Python', 'C++']}>
  <Tab value="Python">

```python
N = int(input())
C = int(input())
P = int(input())

if N <= C * P:
    print("yes")
else:
    print("no")
```

  </Tab>
  <Tab value="C++">

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int N, C, P;
    cin >> N >> C >> P;

    if (N <= C * P) {
        cout << "yes\n";
    } else {
        cout << "no\n";
    }

    return 0;
}
```

</LangTabs>

## J2 Walkthrough: Donut Shop

</ProblemSections>

### Solution

We keep a running total. Start with the \\(D\\) donuts the shop opens with,
then process the \\(E\\) events one at a time: a `+` adds \\(Q\\) donuts, a `-`
removes them. When the events run out, the total is the answer.

The input specification guarantees that every sale has enough donuts in stock,
so the total never goes negative. There is nothing to check and nothing to
clamp.

### Implementation

<LangTabs items={['Python', 'C++']}>
  <Tab value="Python">

```python
D = int(input())
E = int(input())

for _ in range(E):
    event = input()
    Q = int(input())

    if event == "+":
        D += Q
    else:
        D -= Q

print(D)
```

  </Tab>
  <Tab value="C++">

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int D, E;
    cin >> D >> E;

    for (int i = 0; i < E; i++) {
        char event;
        int Q;
        cin >> event >> Q;

        if (event == '+') {
            D += Q;
        } else {
            D -= Q;
        }
    }

    cout << D << '\n';

    return 0;
}
```

  </Tab>
</LangTabs>

## J2 Walkthrough: Dusa and the Yobis

</ProblemSections>

### Solution

This is the first problem where the input has no count — we are not told how
many Yobis there are. We read sizes one at a time and react to each: if the
Yobi is smaller than Dusa, Dusa eats it and grows; if it is the same size or
bigger, Dusa runs away and the process ends.

The problem guarantees that a Yobi big enough to stop Dusa will eventually
appear, so a loop that reads until it breaks is safe. That guarantee is also
why there is no end-of-input handling to write.

### Implementation

<LangTabs items={['Python', 'C++']}>
  <Tab value="Python">

```python
D = int(input())

while True:
    size = int(input())

    if size >= D:
        break

    D += size

print(D)
```

  </Tab>
  <Tab value="C++">

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int D;
    cin >> D;

    int size;
    while (cin >> size) {
        if (size >= D) {
            break;
        }

        D += size;
    }

    cout << D << '\n';

    return 0;
}
```

  </Tab>
</LangTabs>

## Takeaways

None of these problems needs anything beyond input, a condition, and a loop.
What they reward is careful reading: being exactly at capacity still gets you
on the ride, the donut spec promises sales never exceed stock, and Dusa
guarantees the loop terminates.

When a problem feels harder than it should, re-read the specification before
rewriting the code.

The next module applies these habits to problems where the input is text
instead of numbers.
